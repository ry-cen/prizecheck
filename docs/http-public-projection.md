# HTTP public projection adapter

`public_projection_store()` is the sole adapter-selection seam. `PUBLIC_PROJECTION_ADAPTER=filesystem` is the default. To plug in a concrete HTTP manifest relay, set `PUBLIC_PROJECTION_ADAPTER=http`, `PUBLIC_PROJECTION_URL` and `PUBLIC_PROJECTION_TOKEN`. Production requires HTTPS; loopback HTTP is permitted only for local rehearsal. URL credentials/fragments, redirects and weak/missing ETags fail closed. Credentials remain server-side; anonymous routes return only their sanitized snapshot/discovery contracts.

The relay must implement a **linearizable** single JSON manifest object: GET returns `{"format":1,"revision":0,"decks":{}}` and a strong ETag. GET receives `Cache-Control: no-cache, no-store`; do not serve cached or stale replicas. PUT receives the replacement manifest and `If-Match: <ETag>`; atomically accept it only if the current object has that exact ETag. Otherwise return 412. A successful PUT must be immediately visible to all subsequent GETs, with a new strong ETag. Initialization GET404 is followed by PUT with `If-None-Match: *`, creating revision zero only if absent. Other non-success responses are unavailable, never an empty catalog/404. The adapter retries at most three conflicting update attempts, each GET/PUT limited to five seconds. It never caches reads.

All authenticated publication writers acquire a PostgreSQL **session** advisory lock spanning outbox replay and transaction commits. This preserves command order: compare-and-swap alone cannot prevent an older publish replay from resurrecting a revoked URL. All writers must share the same private PostgreSQL database and session-persistent connection; transaction-pooling proxies need a session-capable writer connection. Connection loss releases ownership. Anonymous reads use the projection relay and do not connect to PostgreSQL. Existing private durable outbox, retry idempotency, burned URLs, visibility/discovery revision checks and response allowlists remain in the application.

Run `scripts/init_public_projection.py` only for a genuinely new empty store. Never initialize an empty object over a lost manifest as a recovery workaround. Retain projection state through outages and implement the separate validated private/public recovery reconciliation before cutover.

## Shared records relay (`/records/*`)

Shared catalog, quote and coordination records use a separate record relay under the same base URL and bearer token. It is independent of the manifest above: record operations never change the manifest, its revision or discovery cursors. Ordinary PUT/ETag relays do not satisfy this contract; the adapter fails closed against them. No production relay exists in this repository. The relay is deployment-owned, and `api/tests/public_records_fixture.py` contains the reference relay used by the conformance suite.

Every request is an authenticated `POST <PUBLIC_PROJECTION_URL>/records/<action>` with a JSON body. The body always carries `timeout_ms`, the caller's remaining deadline as an integer from 1 to 30000. The relay must finish or abandon the operation within that time; it must not use its own longer timeout. The client enforces the same total deadline across connect, send and a trickling response, so a late response is discarded as unavailable. Clients reuse pooled keep-alive connections; relays should support HTTP/1.1 keep-alive.

| Action       | Body                                                                                            | 200 response                                                                                                                                                                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `initialize` | `{}`                                                                                            | `{"initialized": true}`. Create the store if it is absent; otherwise do nothing. Never reset or repair established state.                                                                                                                                     |
| `read`       | `{"keys": [..<=128 distinct typed keys], "generation": null \| "<g>"}`                          | `{"generation": "<g>", "records": {"<key>": {"version": "<v>", "value": <json \| null>}}}`. Return exactly the requested keys from one immutable snapshot. When `generation` is given, read that snapshot or fail (503) if it is unknown, expired or corrupt. |
| `transact`   | `{"expected": {key: version}, "changes": {key: value \| null}, "operation_id": null \| "<id>"}` | `{"committed": true \| false}`. Apply all changes atomically only if every expected version is current. Use at most 128 keys. Every changed key must be expected, and `null` deletes.                                                                         |
| `status`     | `{"operation_id": "<id>"}`                                                                      | `{"committed": true \| null}`. Return `true` if that operation committed within the operation TTL; otherwise return `null` (unknown).                                                                                                                         |

Status codes are significant. Return 409 when an `operation_id` is replayed with different `expected`/`changes`. The client raises `OperationConflict`, a programming error, rather than an outage. Return 400 for invalid requests and 401 for a bad token. Return 503 when the relay is unavailable or cannot complete within `timeout_ms`. The client treats every non-200, non-409 response as `ProjectionUnavailable`. It never treats one as empty data.

The relay must provide the same semantics as `FilePublicRecords` (see `api/app/public_records.py`):

- **Linearizable conditional commits.** Exactly one of any number of concurrent contenders for the same version wins, including contenders arriving through different relay processes. A version conflict returns `committed: false` and publishes nothing.
- **Opaque, never-repeating versions.** A missing key has a version too. Delete/recreate, eviction and tombstone compaction must never make an older version, including an older "absent" version, current again.
- **Immutable snapshots.** Reads never block on writers. A superseded generation remains readable for at least 15 seconds so callers can read many 128-key batches at one generation. After that, reads fail closed. Never fall back to another generation.
- **Durable operation IDs.** A committed `operation_id` is remembered for at least 120 seconds. During that time, a replay with identical content returns `committed: true` without reapplying. A failed CAS is not recorded. When a response is lost, the caller resolves the outcome with `status` and then re-reads if needed.
- **Typed keys and capacity.** Reject untyped keys. Only `quote:` payloads are evictable, up to 250,000 entries or 256 MiB, oldest first. Eviction replaces the value with a new tombstone version and never exposes an older value. Catalog (`catalog:printing:`, `catalog:format:`, `catalog:edition:`), quarantine, result/supersession, fence, work (coalescing), admission, lease, backoff and invite (`invite:<64 hex>`, social network #246) records are protected and never evicted. A single value is at most 1 MiB.
- **Fail closed.** Missing or corrupt authoritative state, full storage and interrupted commits return 503 for affected operations. They never revive superseded data.

The client validates every 200 response and treats a malformed one as unavailable: `read` must return a string `generation` (1-128 characters, equal to the requested one when pinned), exactly the requested keys, and a string `version` (1-128 characters) plus a `value` field for each; `transact` must return a boolean `committed`; `status` must return `true`, `false` or `null` (the client reports only "committed" or "unknown").

Run the conformance suite (`api/tests/test_public_records.py`) against any candidate relay before configuring it. With `PUBLIC_PROJECTION_ADAPTER=http`, `scripts/init_public_records.py` and `scripts/init_public_projection.py` call the relay's `initialize` action. The empty-legacy-store upgrade and refusal rules in `docs/public-projections.md` are implemented by the filesystem adapter only; a deployment-owned relay must provide its own equivalent and must never reset established state.

The relay can translate this contract to a selected object provider. A plain vendor object endpoint may not supply linearizable reads, required conditional updates, authentication envelope or initialization behavior; verify or translate those differences before configuring it. No provider was provisioned. Local real-HTTP tests exercise CAS conflict/retry, concurrent writers, revocation/discovery, no-private-database anonymous reads, storage outages, durable failed-write retry, weak ETag rejection and timeouts. Provider latency, capacity and failure recovery still need deployment evidence.
