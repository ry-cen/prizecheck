# Card art is served from our origin through a read-through store keyed by Printing

**Status:** accepted on 2026-10-27. Claude decided it under the owner's delegation of technical plumbing; the owner chose to serve card art from our own origin through a store that saves each image on first request, so the most-used images can later be upgraded to higher resolution (tickets #358 to #361).

The scanner page is cross-origin isolated (`Cross-Origin-Embedder-Policy: require-corp`, [ADR 0017](0017-on-device-recognition-assets-and-the-scanner-index-job.md)), so every scanner `<img>` carried `crossorigin="anonymous"` and the browser ran a CORS check on each image. About 20% of TCGdex's images (81 of 400 sampled) are sent with `Access-Control-Allow-Origin: *` twice, which browsers reject, so those cards showed a broken-image icon in the tray, Scan Suggestion and scanner card search. TCGdex sends no `Cross-Origin-Resource-Policy`, and COEP `credentialless` is not available in Safari, so the pictures have to come from our own origin.

**Decision.**

- **One route, keyed by Printing.** `GET /api/art/{printing_id}/{size}` (`size` is `small` or `large`) is signed-in only, like the scanner routes. It takes no URL: the source is resolved from catalog data (today the active generation's TCGdex `image_url` plus `/low.webp` or `/high.webp`), and the fetcher accepts exactly `https://assets.tcgdex.net`. The route therefore cannot act as an open proxy. Later sources plug into the resolver without changing the route.
- **The store saves each image on its first request.** The fetch has a timeout, a 2 MiB cap, a content-type allowlist (`image/webp`, `image/png`, `image/jpeg`; never SVG) and a magic-byte check, runs at most 5 requests a second and identifies itself as `PrizeCheck-art/1`. Concurrent first requests for one object coalesce into one upstream request. A failure is recorded with backoff (1 minute growing to a day), so a missing file is not refetched on every request. A failure that may pass answers 503 (see the #396 amendment); a Printing with no usable art answers 404.
- **Versioned URLs.** Clients get `/api/art/{id}/{size}?v=<8 hex of sha256(source URL)>`. The version only makes the URL change when the source does; the route never uses it to choose bytes. A request with the current version is cached for a year (`private, max-age=31536000, immutable`); any other request gets the current bytes with `private, no-cache`. Responses carry `Cross-Origin-Resource-Policy: same-origin` and `X-Content-Type-Options: nosniff`, and the gateway streams them as raw bytes.
- **Disk now, S3-compatible later, behind `ArtStorage`.** The interface is `get`, `put` and `delete` by key. The only implementation is a directory (`ART_STORE_DIR`, a bind mount under `PRIZECHECK_DATA_DIR` in the deployed stack) with atomic writes. A storage contract test runs through the interface only, so an object-storage implementation can reuse it. PostgreSQL records each stored object (source, key, sha256, type, size, time), a hit count and last hit per (Printing, size) for a later upgrade job, and the failure ledger.

**Considered options.**

- **A pass-through proxy with no store.** Rejected: it would fetch from TCGdex on every view, hold no per-image state to upgrade, and offer no place to rate-limit or remember failures.
- **COEP `credentialless`.** Rejected: Safari does not support it, and the scanner must work on iPhones.
- **Dropping `crossorigin` from the scanner images.** Rejected: under `require-corp` a cross-origin image without CORS needs a `Cross-Origin-Resource-Policy` header TCGdex does not send, so every image would fail.
- **A named Docker volume for the files.** Rejected: every other persistent mount is a bind mount under `PRIZECHECK_DATA_DIR`, and a volume would be the only state outside it. The deploy script's preflight requires the directory, so Docker never creates a root-owned one the API cannot write to.
- **A database advisory lock to coalesce fetches.** Rejected: the API is one process, and a lock held across a 10 second fetch would tie up a connection. Writes are atomic and upserts idempotent, so a second process would at worst fetch twice.

**Consequences.**

- **The first view of a card is slower, and a cold page may show placeholders.** The rate limit is 5 requests a second; when its queue is more than 10 seconds long a request answers 503 at once and the client shows the plain placeholder, then asks again (#396 amendment).
- **The files are regenerable and stay out of backups.** `backup` archives only `public`. Deleting `art/` costs refetches. Each host runs `prizecheck-deploy.sh setup` once after the script update, because deploys refuse to run without `art/`.
- **TCGdex art is stored, not only linked.** This ADR stores TCGdex copies only. It does **not** copy TCGplayer images: [ADR 0019](0019-tcgcsv-daily-prices.md) chose "linked, not copied" for them, and whether to store them is #361's decision. ADR 0019 lives on the TCGCSV branches until they merge; the file name is the link target.
- **Number clashes are possible at merge.** Migration `156_` and this ADR number were chosen around the TCGCSV branches (migrations 152 to 155, ADR 0018 and 0019); renumber if another branch lands first. #354's planned guardrail on `/low.webp` will flag `art_urls.py`; whoever merges second routes the source through `catalog_printing_art` or allows it.
- **The index job and the API can overlap.** Each is held to 5 requests a second against TCGdex, so a manual index run alongside heavy first views can reach 10 a second. This is documented, not enforced.
- **Art is cached privately for a year.** It is public catalog art and survives sign-out on that device; the cache is `private`, so shared caches do not keep it.

**Amendment (#360): the signed-in app shows art from the route.**

- **The server builds every signed-in address.** `catalog_printing_art` (migration 158) carries `small_art_url` and `large_art_url`, built by `catalog_art_route`, so every signed-in read selects a route address and the client never edits a file name. The Published Deck page and the public catalog keep reading `low_image_url`, so no anonymous response holds a route address. The scanner stays on TCGdex art.
- **One version for both sizes.** `?v=` is the first 8 hex of the sha256 of the Printing's small source URL, for both sizes. A Printing's two files change together, so a large view asks for the same address with `large` in place of `small` and still gets the year-long cache.
- **Fallback art is linked.** The resolver reads the view's chosen source. A TCGdex file is fetched and stored as before. A TCGplayer fallback is not copied ([ADR 0019](0019-tcgcsv-daily-prices.md)): the route answers `302` to the exact `tcgplayer-cdn.tcgplayer.com/product/{id}_200w.jpg` or `_400w.jpg` address the view builds from an integer product id, so a Printing's art still comes from one place. Whether to store TCGplayer copies stays #361's decision.
- **Guardrail.** `scripts/check_guardrails.py` allows `/low.webp` and `/high.webp` only in `api/app/games/pokemon/scanner/scanner.py` and `api/app/games/pokemon/art/urls.py` (the shared-core split, ADR 0023, moved them from `api/app/scanner.py` and `api/app/art_urls.py`), and nowhere in `web/src`.

**Amendment (#396): a temporary failure answers 503, the client retries, and saving a deck warms its art.**

- **503 `ART_UNAVAILABLE` for a failure that may pass.** On prod a deck's pictures stayed as names because every "not now" answer was a 404, the status of a card with no art, and the tiles gave up on the first error. The route now answers **503** with `Retry-After` and `Cache-Control: no-store` for a full rate-limiter queue (5 seconds), a per-Printing lock wait that timed out and a request over the admission cap (3 seconds each), a Printing in backoff (the rest of its wait, at most an hour; the gateway passes `Retry-After` on an art 503) and a fetch that just failed (the backoff that failure starts). A Printing with no art, or a source the route may not use, stays **404 `ART_NOT_FOUND`**. The code stays `ART_UNAVAILABLE`; an `<img>` cannot read the status or the header, so the header is for other clients and the browser relies on the next point.
- **Tiles ask again.** A picture that fails to load is requested again after 1.5 seconds and again after 5 seconds (`web/src/ui/artRetry.ts`) before the card's name or "Artwork unavailable" takes its place for good; while it waits the tile is the plain art surface, with no name, no "Artwork unavailable", no broken image and no word about retrying, and the stand-in appears only once the retries are spent. A Printing in backoff (a minute or more) outlasts those two retries, so only the warm-up or a later visit covers that case. The deck tiles, the Edition tiles (which still try the large file first), the large views and the friend's card images use it. The scanner keeps asking once per page: it counts its requests, and a card that failed there shows the placeholder until the page is reloaded.
- **Saving deck lines warms the deck's art.** After a Deck List command writes lines (adding, changing, removing, importing, the Trading cuts), `art_store.warm_deck` reads the Deck's Printings in the same transaction and queues a background store of the small art of each that has none stored and a TCGdex source (a linked TCGplayer fallback needs nothing). The job runs `serve` on one thread of its own, so it uses the same rate limiter, stripe locks and failure backoff as a request and takes no thread a page is waiting on; it adds no `art_hit`, which counts views. It picks Printings through `catalog_edition` as the lines' display does, is bounded to 200 Printings a save, queues a Printing once while it is queued, and swallows every error, so it never blocks or fails the save. At shutdown the API stops it before its next Printing and drops what is queued. `ART_WARM_UP=0` turns it off; the API tests set it so no test reaches TCGdex.
- **Consequence.** A 503 is a server error to anything counting faults by status. Upstream failures were counted as 404s before; they now count as 5xx, which is accurate (the route could not serve) but moves the owner's fault counts.

**Amendment (#361): TCGplayer copies and public art.** [ADR 0024](0024-store-tcgplayer-art-copies.md) makes TCGplayer's `_in_1000x1000.jpg` a stored `large` source, used when it is sharper than TCGdex's art, and opens the route to the signed-out Published Deck page and the public catalog.

**Amendment (#438, #439): how TCGplayer large art and public art work.**

- **One TCGplayer product per Printing.** `catalog_printing_art_product` holds the product chosen from a Printing's verified Editions with a current price binding, by the same rule as the fallback; it is refreshed after each fallback refresh. A Printing with fallback art uses its fallback product, so its small and large art come from one product.
- **The comparison runs on the first large request.** Under the (Printing, `large`) lock the route fetches `_in_1000x1000.jpg` first and reads its size from the JPEG header. It wins when it has more pixels than 600×825, or, against the linked `_400w`, when it is at least 400×558. A winner is stored and served and TCGdex's large file is not fetched. `art_large_upgrade` records the outcome (`won`, `lost` or `failed` with backoff), so a loser is not fetched again while the two sources stay the same.
- **The version covers the upgrade.** `?v=` is unchanged for a Printing without a stored winner. With one it is the first 8 hex of the sha256 of the small source and the winning address, for both sizes; a small request accepts either version as current.
- **`ART_TCGPLAYER_SOURCE` turns it off.** `on` (the default) or `off`; any other value is off. Off stops new TCGplayer copies at once, the next view replaces a stored one, and `scripts/art_store.py purge-tcgplayer` deletes the stored objects and their records.
- **Public art reads no database.** `GET /api/public/art/{printing_ref}/{size}` serves a stored image through a pointer file kept next to it (`public/{size}/…`), so anonymous Published Deck access still makes no PostgreSQL connection. Published Deck and Discover reads give a public address for stored art and today's direct address otherwise; publishing warms both sizes of the deck's art, and `scripts/art_store.py pointers` writes pointers for images stored earlier. Stored art on a Published Deck follows the Printing's current art, as signed-in pages do, so a snapshot no longer keeps the stored art it was published with ([ADR 0019](0019-tcgcsv-daily-prices.md) Consequences); art that is not stored keeps the snapshot's direct address. The gateway limits public art to 600 requests a minute per IP, apart from other public reads, and the responses are `public, max-age=31536000, immutable` for the current version and `public, no-cache` otherwise.
