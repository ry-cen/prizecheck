# On-device recognition assets and the scanner index job

**Status:** accepted on 2026-10-22, amended 2026-10-25. Claude decided it under the owner's delegation of technical plumbing for the [card scanner map](../planning/card-scanner/wayfinder/map.md). The owner accepted the fingerprint-rights limit and the iOS eviction on 2026-10-22, and the 4-thread runtime after the phone gate on 2026-10-23. The reasoning is in the [plumbing resolution](../planning/card-scanner/wayfinder/resolutions/decide-scanner-plumbing.md) (D3, D4, D9; D1 as amended) and the [spec](../planning/card-scanner/spec.md) (Web and delivery, Device storage and the Scan Tray).

The scanner recognizes cards on the collector's phone, from about 40 MB of models and a card index that follow the catalog, not deploys. No ADR covered static assets, caching or an ML build job, and several of these choices look odd without the constraints behind them: the index is not on a CDN, the scanner is a page of its own, and the Scan Tray lives in the browser.

**Decision.**

- **Models are static assets in the web image.** The embedder, the OCR recognizer and its dictionary are pinned by sha256 in `web/scanner-models.lock.json`, fetched from the model host at image build by a Node script, and served by nginx under a content-addressed `/scanner/m/` path with immutable caching and gzip. Git never holds them.
- **The fingerprint index is catalog data, built by a separate job image.** A portable job (`scanner-index`) embeds the catalog's reference artwork, writes the int8 fingerprint file to PostgreSQL, and keeps the two newest artifacts per model. The API serves it only to signed-in collectors, as an attachment the gateway streams unchanged. The job carries the ML dependencies, so the API image does not. No scheduler is installed for the job itself ([ADR 0002](0002-defer-deployment-provider-selection.md)); the operator runs it after catalog pulls. Amended 2026-10-27: on production the daily catalog refresh timer runs it ([ADR 0018](0018-scheduled-catalog-change-check.md)).
- **The device keeps blobs in Cache Storage and the Scan Tray in `localStorage`.** Models, the fingerprint file and the number table are stored under content-addressed URLs and verified before they are stored. The Scan Tray is one small JSON value per account, written under a Web Lock. Nothing the tray holds is an image, a name or a price.
- **The scanner is its own cross-origin-isolated HTML entry.** It is served at `/collection/scan` with `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`, so the WASM runtime can use up to 4 threads (one when isolation is missing). COEP is also sent on `/assets/` and repeated in the nested `.mjs` location, because the recognizer worker script and the runtime's threaded glue are loaded by the isolated page and must carry COEP themselves. Every way into the scanner and out of it is a full navigation.

**Considered options.**

- **A CDN or a public index.** Rejected. The index is derived from TCGdex artwork, which is The Pokémon Company's copyright, and [card image sources](../planning/tcg-collection-tracker/wayfinder/research/card-image-sources.md) finds nothing licensed for re-hosting. No CDN exists ([ADR 0002](0002-defer-deployment-provider-selection.md)), and one would add an origin for CSP and privacy.
- **Models in git or LFS.** Rejected: about 32 MB per version, kept forever. Serving them through the API was also rejected, because the gateway would stream them uncached through Node.
- **Building the index in the API image.** Rejected: about 200 MB of ML dependencies on every replica, and the catalog import's post-commit hook runs in the API container. A shared volume read by nginx was rejected because it would make the index public and the web container is read-only on the edge network.
- **OpenCV.js.** Rejected: about 10 MB more download for about 12 functions the pipeline uses. The image work is hand-written TypeScript pinned to the spike's Python by parity fixtures ([D2](../planning/card-scanner/wayfinder/resolutions/decide-scanner-plumbing.md#d2-image-work-is-hand-written-typescript-not-opencvjs)).
- **IndexedDB, OPFS, a service worker or the HTTP cache for storage.** Rejected: IndexedDB's transactions buy nothing for about 80 KB with the same eviction class; OPFS handles are worker-only; a service worker adds a PWA surface the product does not otherwise have; the HTTP cache evicts unpredictably and cannot be verified.
- **Isolating the whole app, or running one thread.** Single-threaded WASM was the first plan, but the phone gate ran 4 threads and still missed its speed bars (2 threads were slower, 451 ms against 393 ms per frame), so one thread was not kept; 4 threads need isolation. Isolating the whole app would put COEP on every page and every cross-origin image for the sake of one screen, and Safari has no `credentialless` mode to soften it. Only the scanner document carries it.
- **WebGPU or a native plugin.** Not chosen now. They remain replacements behind the recognition module interface, along with a faster port, without changing the tray or the save path.

**Consequences.**

- **The header scope is deliberate.** COOP and COEP go on the scanner's HTML document and on no other HTML document. COEP also goes on `/assets/` responses and the nested `.mjs` location (nginx does not inherit `add_header` into nested locations); on non-document responses it has no effect on the main app. Every `<img>` in the scanner needs `crossorigin="anonymous"`. The phone gate never met this, because the spike sent both headers on every response. A test must show `self.crossOriginIsolated` is true inside the worker, not only on the page.
- **The index is never public.** It sits behind sign-in, outside git and the web image, and the job's fetches are rate-limited and identify PrizeCheck. This is why the scanner may run only on the private, sign-in-only deployment. A public launch waits for a written rights check, and stays a ship blocker ([spec](../planning/card-scanner/spec.md#ship-blockers)).
- **Safari may delete the Scan Tray.** After 7 days without opening PrizeCheck, or under storage pressure, an iOS Safari tab loses it, models included. The owner accepted this with no note in the UI. The app asks for persistent storage once; Chrome grants it quietly, Safari mostly for Home Screen apps.
- **The index can lag a catalog pull.** Without a scheduler, a new set is matched by number at once (the number table is built by the API on request) and by artwork only after the operator runs the job. A model change is a new model id: build its artifact first, then deploy the web image.
- **The index costs storage and backup.** About 8 MB per artifact, two kept per model, in PostgreSQL. The artifacts can later move to the private object-store factory by changing only the serving route.
- **The first open downloads about 40 MB.** It starts at once with a progress bar and no cellular warning, which the owner accepted.
- **The runtime is provisional, the boundary is not.** The 4-thread WASM runtime missed the phone gate's speed bars and shipped anyway (owner, 2026-10-24). Replacing it must not change the isolated entry's contract with the tray, the save route or the asset layout described here.
