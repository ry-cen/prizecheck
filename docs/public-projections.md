# Local public Deck object projection

Anonymous Deck reads open only the sanitized projection in `PUBLIC_PROJECTION_DIR` (default `.local/public-projections`). They never connect to PostgreSQL or look up a session. The JSON response allowlist is defined by `PublicSnapshot`; nested models reject extra fields. React renders source metadata and titles as text. Unlisted snapshots use `noindex, nofollow`, and all snapshot responses use `Cache-Control: no-store`.

Before starting a NEW local environment, initialize its empty object store:

```sh
PUBLIC_PROJECTION_DIR=/absolute/path/public-projections .venv/bin/python scripts/init_public_projection.py
```

For an EXISTING install that predates shared records, initialize only the records store. The same command upgrades an empty legacy records store and does nothing for an established store:

```sh
PUBLIC_PROJECTION_DIR=/absolute/path/public-projections .venv/bin/python scripts/init_public_records.py
```

It never touches the publication/discovery manifest. It is idempotent and creates the store only when no records files exist. It exits with status 1 and changes nothing if established records are missing or corrupt, if a leftover `initialized` marker or generation files exist without a valid pointer, or if a legacy (format-1) records store holds data. Restore those from backup rather than resetting them. There is no in-place migration of a populated legacy store; no such store was written by production code. A new environment's `init_public_projection.py` initializes both stores, so this script is not needed there (running it afterwards is harmless). With the HTTP adapter the script calls the relay's `initialize` action (`docs/http-public-projection.md`).

Keep that path in the API environment and outside any static-file web root. All API processes must share the same writable filesystem. The local adapter uses a process lock, fsync, and atomic file replacement to switch the complete public snapshot/discovery manifest. No public snapshot history is retained. The adapter assumes macOS/Linux filesystem semantics and is a development boundary; deployment provider selection must supply shared storage with equivalent serialization and atomic updates. Public snapshots and their visibility are the only content in this projection; owner linkage, command records, and token tombstones remain private PostgreSQL data.

A publication command commits its token linkage and a sanitized projection operation to a durable private outbox, then applies the public operation. It returns success only after the complete object switch. An interrupted or failed object write returns `503 PUBLICATION_UNAVAILABLE`; the prior complete object remains available when replacement did not occur. Retry with the same idempotency key. Any subsequent authorized publication command first drains pending operations in order, so it cannot overwrite a newer result with an older retry. A crash after the object switch repeats that same operation safely. No scheduler or polling worker is required. Revocation removes the public token object and permanently records the burned token privately; publishing again generates a fresh 192-bit token.

Missing or corrupt object storage returns `503 PUBLIC_PROJECTION_UNAVAILABLE`, rather than pretending the Deck was deleted. Do not initialize an empty manifest to recover lost storage. Restore the public store from its backup, or rebuild it from the private publication command history with revoked-token and visibility state preserved. Back up this private command history together with publication linkage. Never expose those private tables or records through an anonymous route. A public store failure does not report successful publication or revocation.

CI must use a disposable database and a fresh `PUBLIC_PROJECTION_DIR`, initialize the store before browser tests, and remove it afterward. Individual HTTP tests isolate their object stores. Hosting and object-storage vendors remain unselected under ADR 0002.

Listed visibility changes reuse the same atomic manifest switch and private outbox, so discovery, sitemap, and snapshot indexing headers change together. Visibility changes preserve snapshot content and version. Public search matches the public title, an included Card Identity name, or an included row's own Card Printing name (so "Juniper" finds "Professor's Research (Professor Juniper)"), orders by publication time and stable token, and returns 30 summaries per page. Signed cursors bind the normalized query, the format filter and monotonically increasing projection revision; any intervening publication mutation returns `409 DISCOVERY_CHANGED`, and the UI restarts at page one. Public discovery and `/api/public/sitemap.xml` read only sanitized public objects.

The local auth gateway can enforce anonymous public-read budgets with `PublicReadLimiter` from `auth/src/publicReads.ts`. Mount it before proxying snapshot, discovery, and sitemap GET requests, using the existing trusted-proxy client address derivation. It retains only randomly salted caller digests in a bounded in-memory one-minute window, clears them on expiry, and writes no IP addresses or caller counts to PostgreSQL. The default is 120 reads per caller per minute. Return 429 with Retry-After when exhausted. Production edge selection must provide equivalent rate limiting across replicas; the local helper protects the single gateway process.

### Deck List snapshots (Deck Lists 09)

Publishing and republishing freeze the Deck's Deck List lines (ADR 0009), never its Holdings: one row per Card Edition with its line quantity, whether the owner holds those copies in the Deck, elsewhere or not at all. A snapshot is identical for the same Deck List whatever the owner holds or where, so it reveals nothing about ownership or Locations. Rows still group by Card Identity, whose name and total drive the copy counts and basic checks. Each row (`PublicEdition`) also carries `printing_name`, the row's own Card Printing name with its subtitle (for example "Professor's Research (Professor Juniper)"), which Mass Entry lines, Live blockers and discovery search use.

Snapshots published before Deck Lists 09 have no `printing_name`; they stay valid and are never rewritten. The snapshot route answers `printing_name: null` for them, and readers fall back to the row's Card Identity name, which those snapshots froze with any subtitle. A runtime older than Deck Lists 09 rejects `printing_name` (`PublicEdition` forbids extra fields). After a snapshot is published or republished on Deck Lists 09, rolling the application back to such a runtime makes that snapshot answer `503 PUBLIC_PROJECTION_UNAVAILABLE`. While one such snapshot is Listed, discovery and the sitemap answer 503 for every deck, not only that one, and visibility changes fail on the old runtime. Revoking the snapshot is the clean recovery after a rollback; republishing on the old runtime replaces it, but publishes the Deck's Holdings rather than its Deck List. To avoid the rollback hazard, release in two steps (expand/contract): first ship a reader-only `printing_name: str | None = None` on `PublicEdition`, then ship the writer that publishes it.

### Target Format and the publish gate (app redesign #178)

Every Deck List has one Target Format (`deck_list.target_format`, migration 045: `standard`, `expanded` or `glc`, Standard by default and for every Deck List that existed before), and publishing needs a `legal` result in it (ADR 0011).

- **Gate.** Publish (`POST /api/decks/{deck_id}/publication`) and republish (`PUT`) recompute the Deck List's result in its Target Format for today inside the command's transaction, after the owner row is locked and the catalog row share-locked, so the result and the snapshot read the same Deck List and catalog. Anything but `legal` answers `409 TARGET_FORMAT_NOT_LEGAL` with `detail: {code, target_format, format_checks}`, where `format_checks` is the private format-checks body (`deck_id, deck_list_revision, attribute_revision, catalog_revision, results, disclaimer`) with the one result. `unknown` is refused like `not_legal`. A refusal writes nothing: no publication row, no outbox row, no object change, and the discovery revision stays where it was. A stored command still replays its stored result first, so a publish whose response was lost replays even after the Deck stops being legal.
- **Snapshot.** `PublicSnapshot.target_format` freezes the Target Format the snapshot was published in. A snapshot published before this release has no `target_format`; it reads as `standard` (the model's default) and its stored object is never rewritten, so its digest, and every enrichment answer bound to it, is unchanged. Visibility changes keep the stored bytes, as before.
- **Rollback.** `PublicSnapshot` forbids extra fields, so a runtime older than #178 rejects a snapshot that carries `target_format`, with the same consequences as `printing_name` (Deck Lists 09 above): that snapshot answers `503 PUBLIC_PROJECTION_UNAVAILABLE`, and while one is Listed, discovery and the sitemap answer 503 for every deck. Revoke snapshots published on #178 before rolling back past it, or ship a reader-only `target_format` first.
- **Tests.** Publishing tests written before the gate publish small Deck Lists that aren't legal, so they exempt the Decks they publish through `api/tests/catalog_process_fixture/publish_gate_fixture.py` (`test_publications.command` does it in pytest; `web/tests/support/publish-gate.ts` in browser specs). Only the verification stacks load that hook; the gate's own tests (`api/tests/test_publish_gate.py`) exempt nothing.

Public format checks for a snapshot version still answer every Format; answering only the snapshot's Target Format is the Published Deck page's change (#183).

### Discover lists legal decks (app redesign #182)

`GET /api/public/discovery` lists only the Listed snapshots that are `legal` in their Target Format today (ADR 0011), newest first, 30 to a page. It still reads the manifest for the snapshots and makes zero session and PostgreSQL access; the format facts and quotes it judges them by come from the shared records store, so like the other enrichment reads it follows a correction only after outbox delivery.

- **Result.** Each snapshot is judged by the Published Deck format results' own evaluation (`published_format_checks.checks_for`, over `read_facts`), so Discover lists a deck exactly when `GET /api/public/decks/{token}/versions/{version}/format-checks?format=<its target_format>` answers `legal`. The result is cached in the API process by the snapshot digest, the Target Format, its rules file's SHA-256, the deciding code's SHA-256 (`discovery.CODE_SHA256`), the rule-date window (the next rule date after today) and the public format-fact revision (`discovery.facts_revision`: a digest of every format fact the check reads, each row's Printing and every printing of their Reprint Groups). The facts are read on every request, because reading them is the confirmation: a deck whose facts can't be read in time (records store unavailable, or past `DISCOVER_SECONDS`) is never listed from a cached result. When the walk stops on that with decks already shown, the answer carries a `next_cursor` keyed on the last shown deck so older Listed decks stay reachable; when it stops with nothing confirmed, the answer is `503 PUBLIC_CATALOG_UNAVAILABLE` (an outage, not an empty Discover). A readable store that confirms no legal deck is a `200` with no decks. A legacy snapshot (rows without references) and one whose format records predate migration 038 are `unknown`, so they stay out until a republish or `scripts/backfill_public_catalog.py`.
- **Summary.** Each summary keeps `url, title, total, published_at, checks, image_url` and gains `featured_name` (the featured card: the rule-box Pokémon with the most copies, else the Pokémon with the most copies, else the first card with art; `image_url` is its art), `target_format`, `target_format_status` (always `legal` in a listing) and `cost: {amount, priced_copies, total_copies}`. The cost reads the cached quotes only, at the same store generation as the facts, with the Published Deck cost route's eligibility proof and arithmetic; `amount` is null when no copy is priced. Stale quotes count as priced, no age is sent, and Discover never admits a refresh or writes a record.
- **Filter and cursor.** `format=standard|expanded|glc` narrows by Target Format (anything else is `422 UNKNOWN_FORMAT`). Cursors are version 2 and bind the query, the format and the manifest revision; a version 1 cursor from before this release is `400 INVALID_CURSOR`, and the page restarts at page one. A deck that turns legal or not legal between two pages moves no revision, so a later page simply includes or skips it.
- **Sitemap.** `/api/public/sitemap.xml` is unchanged: it lists every Listed snapshot, legal or not.
- **Tests.** Listing tests written before this change list small Deck Lists that aren't legal, so `test_discovery.visibility` exempts each snapshot it lists by token (`publish_gate_fixture.exempt_listing`; `web/tests/support/publish-gate.ts` and the auth suite write the same `discover-exempt/<token>` file). `api/tests/test_discover_listing.py` and `web/tests/discover-page.spec.ts` exempt nothing.

### Published Decks outlive their Deck (Deck Lists 10)

Deleting a Deck (`DELETE /api/decks/{deck_id}`) moves its Holdings to Unsorted and deletes the Deck and its Deck List. Its publications only lose their link to it: migration 032 makes `deck_publication.deck_id` nullable with `ON DELETE SET NULL`. An active publication stays live with its snapshot, visibility, discovery listing and token unchanged, because none of those depend on the Deck. Nothing is written to the projection or the outbox when a Deck is deleted.

The owner manages publications by token, with or without a Deck:

- `GET /api/publications` lists the owner's active publications (`token, version, title, visibility, deck_id, projection_pending`); `deck_id` is null once the Deck is deleted.
- `DELETE /api/publications/{token}` revokes, and `PATCH /api/publications/{token}/visibility` changes visibility. Both take the same bodies, idempotency keys, outbox and `PublicationResult` as the Deck-keyed routes.
- A malformed, unknown or other owner's token is `404 PUBLICATION_NOT_FOUND`, checked before the projection store is opened. The owner's own revoked token is `409 PUBLICATION_REVOKED`, but during a store outage every owner command answers `503 PUBLICATION_UNAVAILABLE` first, a revoked token's included, because the store is opened before the publication's state is read.
- A retried command, Deck-keyed or token-keyed, replays its stored result before any ownership or state check (after the public store opens, so during a store outage it answers 503), so a retry whose first response was lost still answers it after the Deck is deleted. A reused key with another request is `409 IDEMPOTENCY_KEY_REUSED`.

A publication without a Deck cannot be republished: republishing snapshots a Deck List, and only the Deck-keyed `PUT` exists, which answers `404 DECK_NOT_FOUND` once the Deck is gone. `one_active_deck_publication` still allows at most one active publication per existing Deck; unlinked publications have a null `deck_id`, which the unique index never compares, so any number of them can stay active.

**Lock order.** Every publication command takes, in order: the session advisory lock that serializes publication commands and outbox delivery, then the inventory-owner row (`FOR UPDATE`), then the Deck's row and its publications. Deck deletion and every inventory and Deck List command (Add, Move, undo, Edition reassignment, Pick List confirmation, Deck List edits) take the owner row first too, and none of them takes the advisory lock, so no cycle is possible.

The owner row must come first because publication commands insert `deck_publication` and `publication_command` rows, whose foreign keys key-share lock the owner row and the Deck's row, while a Deck deletion holds the owner row and then needs the Deck's publications (`ON DELETE SET NULL`). A visibility change reads and validates the public object before its transaction, so the owner row is never held across store I/O.

A publication command racing a deletion therefore runs wholly before it (and its publication is then unlinked and stays live) or after it (Deck-keyed commands answer `404 DECK_NOT_FOUND`; token-keyed ones still succeed).

**Rollback.** A runtime older than Deck Lists 10 runs against migration 032 unchanged: it never deletes a Deck, always writes `deck_id`, and finds publications only by `deck_id` equal to a Deck, which never matches a null. Its anonymous reads never touch `deck_publication`. What it cannot do is reach an unlinked publication: it has no token routes, so a publication whose Deck was deleted stays live and cannot be revoked or changed until the application is rolled forward. Revoke such publications before rolling back if they must come down. While an older runtime and this one serve side by side during a release, an older runtime's publication command still locks the owner row late, so it can deadlock with a Deck deletion on the new runtime. PostgreSQL aborts one of them: the deletion answers `503 INVENTORY_TEMPORARILY_UNAVAILABLE` and the publication command `503 PUBLICATION_UNAVAILABLE`, nothing is half-applied, and either can be retried with the same idempotency key.

### Nested anonymous routes

The gateway treats every `/api/public/` path as an anonymous GET: no session lookup, no identity forwarded, whatever cookies arrive. No public route takes another method, so the gateway answers any other method (HEAD included) with 405 before it reads a body or looks up a session. A budgeted public route is signed with an `anon:` caller. Enrichment routes under a snapshot (`/api/public/decks/{token}/versions/{version}/...`: the Published Deck cost, the four Published Deck export routes and the Published Deck format results) reach a snapshot only through `api/app/public_deck.py`. A route calls `public_path` (query, body and syntax; a route may name the query parameters it accepts, each at most once), then `read_active`, then its own eligibility read, then `revalidate` before it responds; `same_printing` proves a frozen row's reference against the Printing the public catalog records name. `public_deck.printing_matches` is the one proof rule behind both `same_printing` and `published_cost`. `SnapshotGone` is 404 `PUBLISHED_DECK_NOT_FOUND`, `SnapshotChanged` is 409 `PUBLISHED_DECK_CHANGED`, for the cost route, `SnapshotLate` is a withheld `deadline` answer, and `ProjectionUnavailable` is 503 at entry but a withheld `validation_unavailable` answer at the final check. The module validates the token and version syntax and rejects any query string the route does not name and any body, reads the active frozen snapshot from the manifest under the caller's deadline (derived rows, opaque references, quantities, and a digest of the frozen content), and re-reads it before a response so that a revoke (404), a republish or a rewritten snapshot (409) is never answered with enrichment computed for other content. Enrichment never writes the manifest, so the discovery revision is unchanged by quote updates and runner writes.

Export routes are unbudgeted and use `read_for_export`/`revalidate_for_export`, which map every failure to an HTTP error (no withheld answer).

### Published Deck format results (Deck Lists 18)

`GET /api/public/decks/{token}/versions/{version}/format-checks` answers `PublishedDeckFormatChecks` (`version, digest, results, disclaimer`). Each result has the private route's shape (`format, status, issues, rules_version, evaluated_on, notes, computed_at`; an issue is `code, reason, kind, effect, lines`), and the private route's `?format=` and `?as_of=YYYY-MM-DD` work the same way: `as_of` defaults to today in UTC and a future date carries the private route's note. Only an issue's `lines` differ: they are the frozen rows' public Edition references, or `row:<n>` (the row's 0-based position among the snapshot's rows) for a legacy row without one. Public results are never saved, so `computed_at` is always the request's time. No answer contains an internal UUID, owner, Deck id, Deck List revision, attribute revision or catalog revision.

Results are recomputed on every read from the frozen rows and quantities and the current public format facts (`catalog:format:<ref>`, below), with the private route's pure evaluator and rules files. They therefore follow rotations, bans and set-legality dates, reviewed attribute corrections, re-derived attributes, Reprint Group changes and Card Identity merges without republishing, after outbox delivery (the same lag as prices). The snapshot's own frozen basic checks (`checks`) never change; a Published Deck keeps its frozen Basic Energy result until it is republished.

A row is proven when its frozen Printing reference has a well-formed format record. A record must carry exactly the current attribute keys, so a record written before migration 038 (no `basic_pokemon`) is malformed until `scripts/backfill_public_catalog.py` rewrites it (docs/operations/release.md). A legacy row without references, a row whose record is missing or malformed, and rows of one Edition with different Printing references are checked with unknown facts under their frozen Card Identity name: they count toward size and copy limits, never make a result legal, and report one `card_data_unavailable` gap instead of their set and regulation-mark gaps. A row whose Printing is in a Reprint Group is proven only when every printing the group's record lists has a well-formed format record naming the same group; the evaluator then judges reprint legality and bans through the group exactly as the private route does (`format_evaluator.line_standing`).

| status | code                            | when                                                                                             |
| ------ | ------------------------------- | ------------------------------------------------------------------------------------------------ |
| 422    | `INVALID_REQUEST`               | a body, a query parameter other than `format` and `as_of`, or either given twice                 |
| 404    | `PUBLISHED_DECK_NOT_FOUND`      | bad token or version syntax, a token not active at entry, or no longer active at the final check |
| 422    | `UNKNOWN_FORMAT`                | `format` names no format with a rules file                                                       |
| 422    | `INVALID_AS_OF`                 | `as_of` is not a `YYYY-MM-DD` date                                                               |
| 409    | `PUBLISHED_DECK_CHANGED`        | another active version, or the digest changed between entry and the final check                  |
| 503    | `PUBLIC_PROJECTION_UNAVAILABLE` | the manifest is unreadable, invalid or late, at entry or at the final check                      |
| 503    | `PUBLIC_CATALOG_UNAVAILABLE`    | the record store is unreadable or late while format facts are read                               |

The route is unbudgeted and synchronous like the exports: one `EXPORT_SECONDS` deadline bounds the entry read, the format-fact read and revalidation, and every answer and route-raised error carries `PUBLIC_HEADERS`. It makes zero session, PostgreSQL and private-inventory access, writes no record and leaves the manifest bytes and discovery revision unchanged (`api/tests/test_published_format_checks.py`; the absent, forged and valid cookie proof through the real gateway is in `auth/tests/published-cost.test.ts`).

### Published Deck exports (tickets 13 and 14)

Four anonymous routes export the active frozen snapshot, and take only a token and a version:

- `GET /api/public/decks/{token}/versions/{version}/exports/live` answers `PublishedLiveExportView` (`version, digest, status, text, inline, byte_length, total_copies, blockers`);
- `.../exports/live.txt` streams the Live text;
- `.../exports/tcgplayer` answers `PublishedMassEntryView` (`version, digest, status, url, fallback_reason, text, inline, byte_length, lines, line_count, less_specific_count, total_copies`);
- `.../exports/tcgplayer.txt` streams the Mass Entry text.

Any query string or body is `422 INVALID_REQUEST`; POST is the framework's 405. Every answer and every route-raised error carries `PUBLIC_HEADERS` (`Cache-Control: no-store`, `Pragma: no-cache`, `X-Robots-Tag: noindex, nofollow`). No answer contains an internal UUID, owner id or Deck id.

| status | code                            | when                                                                                             |
| ------ | ------------------------------- | ------------------------------------------------------------------------------------------------ |
| 422    | `INVALID_REQUEST`               | a query string or a body                                                                         |
| 404    | `PUBLISHED_DECK_NOT_FOUND`      | bad token or version syntax, a token not active at entry, or no longer active at the final check |
| 409    | `PUBLISHED_DECK_CHANGED`        | another active version, or the digest changed between entry and the final check                  |
| 503    | `PUBLIC_PROJECTION_UNAVAILABLE` | the manifest is unreadable, invalid or late, at entry or at the final check                      |
| 503    | `PUBLIC_CATALOG_UNAVAILABLE`    | the record store is unreadable or late while eligibility is read                                 |
| 422    | `DECK_EMPTY`                    | `.txt` of an empty snapshot                                                                      |
| 409    | `LIVE_EXPORT_BLOCKED`           | `live.txt` while any row blocks                                                                  |

Exports have no withheld answer: a failure is an error, and the snapshot route stays available.

**Deadline.** One deadline of `EXPORT_SECONDS` (5 s) is computed per request and bounds the entry read, the eligibility read and revalidation. The routes are synchronous, because the HTTP record adapter refuses to run on an event loop. Each route reads the snapshot, reads eligibility, builds the export, then revalidates (token, version, digest) before it answers, including before a `.txt` stream starts, so a revoke gives 404 and a republish or same-version rewrite gives 409.

**Live.** A row's Printing is proven when its frozen Printing reference is present and `live_states` resolves it to a well-formed public Printing record. Marketplace state is never read, so a quarantine of the Edition never changes or blocks Live. The text uses the current reviewed identity of that Printing; blockers show the frozen name, set, number and descriptor. An unproven row blocks with reason `unproven_reference` and the snapshot stays readable; an unsupported or suspended Printing blocks every row of that Printing with its reviewed reason (and so the whole export).

**Mass Entry.** A row gets a product only when `marketplace_states` says the Edition is `product_eligible`, `same_printing` holds against the Edition record's Printing, and the frozen variant is known (not the Unspecified Variant). A quarantine turns the link into complete `missing_mapping` text at once. There is one line per proven Printing; unproven rows stay on their own name-only lines, labelled less specific. There is no specificity crosswalk, so the row's frozen Card Printing name is the line name (the Card Identity name for a snapshot published before Deck Lists 09).

**Reuse.** Formatting, grouping, blocking, fallback, the inline limit, the URL limit and the downloads come from the private formatters (`live_export.format_live`, `mass_entry_export.format_mass_entry`) and the shared `export_fields`/`view_fields`/`text_download` helpers in `deck_live_export` and `deck_mass_entry`. The private routes are unchanged.

**Legacy rows.** A snapshot row without references is never proven, because no store of preserved reviewed publication evidence exists and association sidecars and private lookups are forbidden. Live blocks it with `unproven_reference`, Mass Entry uses a name-only line, and a republish recaptures the references.

**Digest.** The digest is returned for diagnostics and checked server-side within a request (a change is 409); it is never an input. The client discards an answer for another version and re-reads the snapshot on 409 or 404. The export routes did not change the snapshot route or its allowlist (an owner decision); Deck Lists 09 later added `printing_name` (see "Deck List snapshots").

**Eligibility lag.** Eligibility comes from the store's `catalog:*` and `quarantine:*` records, so a PostgreSQL decision, suspension or quarantine reaches the exports only after outbox delivery, as for prices.

**Isolation.** The routes make zero session, PostgreSQL and private-inventory access, write no record, and leave the manifest bytes and the discovery revision unchanged. They are proven by `api/tests/test_published_live_export.py`, `api/tests/test_published_mass_entry.py`, the export test in `auth/tests/published-cost.test.ts` (zero gateway and API database connections for absent, forged and valid cookies), `web/tests/published-live-export.spec.ts` and `web/tests/published-mass-entry.spec.ts`.

**Launch gates.** Actual Live import per supported case and actual Mass Entry product and text acceptance remain separate, independent launch-checklist gates. Automated tests are not destination acceptance. No rule is activated.

## Shared public records

Public catalog metadata, quotes, quarantine, and refresh coordination live in `PUBLIC_PROJECTION_DIR/records`, separate from the Deck manifest. Record writes never change the manifest, its revision, or discovery cursors. `api/app/public_records.py` defines the typed key families and the store API. The HTTP relay equivalent is in `docs/http-public-projection.md`.

The filesystem adapter stores immutable content-addressed generations behind one atomic pointer file. Its index has 4,096 shards, so a commit rewrites only the touched shards and a small manifest. Writers serialize on a shared `flock`. Reads take no lock, write nothing, and see one consistent generation. Only `quote:` payloads are evictable, up to 250,000 entries or 256 MiB, oldest first. Every other family is protected. A failed conditional commit writes nothing.

Cleanup runs only during writes. It is incremental and best-effort, so a cleanup failure never fails a commit. Cleanup always keeps the current generation and every generation superseded within the last 15 seconds. Readers can therefore pin one generation across many 128-key batches; after that window, reads of the old generation fail closed. The operation log keeps explicit operation IDs for 120 seconds. Deleted-record tombstones are compacted after 10 minutes without making old versions valid again.

Back up the `records` directory with the rest of the projection directory. A copy taken without stopping writers can capture a pointer that names a generation absent from that copy. If so, restore from a quiescent copy. Missing, corrupt, or full storage returns unavailable rather than older data. Do not delete files by hand or re-initialize over lost state.

## Public catalog records: reviewed state, outbox and delivery

`api/app/public_catalog.py` is the only writer of the `catalog:printing:<ref>`, `catalog:format:<ref>`, `catalog:edition:<ref>` and `quarantine:edition:<ref>` records. PostgreSQL is authoritative; the store is a derived, rebuildable copy. Values are exact allowlists. No internal UUID, source ID, owner, reviewer, evidence URL, free-text reason, report, reporter, rejected fingerprint, source candidate or quote amount is ever published.

```
catalog:printing:<ref>   {printing_ref, name, set_id, set_name, collector_number, image_url,
                          revision,
                          live: {state: unsupported|eligible|suspended, reason: <code|null>, rule_version: <int|null>,
                                 identity: {category, name, set_code, number} | null}}
catalog:format:<ref>     {printing_ref, revision, set_id: <text|null>, collector_number: <text|null>,
                          identity: {key, name}, reprint_group: null | {ref, printings: [<printing ref>]},
                          attributes: {regulation_mark, card_kind, basic_energy, types, rule_box, ace_spec, radiant,
                                       prism_star, basic_pokemon}}
catalog:edition:<ref>    {edition_ref, printing_ref, descriptor, revision,
                          marketplace: {state: unverified|verified|quarantined, reason: <code|null>, mapping_revision,
                                        product_id: <int|null>,
                                        quote_lookup: {source: "tcgdex", card, variant} | null}}
quarantine:edition:<ref> {edition_ref, revision, mapping_revision, state: clear|quarantined}
```

A Printing record's `name` is the Printing's own display name (with the subtitle, e.g. "Professor's Research (Professor Juniper)"); only a Printing without display data falls back to its Card Identity name. Releases before migration 028 published the Card Identity name instead; after 028, do not run a public catalog rebuild on a runtime rolled back to such a release, because it would treat the renamed records as conflicts at the same revision and suspend Live. `revision` is the commit-ordered public review revision (`public_revision`). `product_id` is published only while the Edition is verified. `quote_lookup` is published only while it is verified and has a reviewed quote variant. Live identity is published only while the Printing is eligible. Reason codes are the fixed enums in migration 023.

A format record (Deck Lists 18) holds the public card facts a Published Deck format check reads: the Printing's immutable display `set_id` and `collector_number` (null without display data; ban lists name printings by them), its Card Identity's unique `key` (which groups copy limits) and display `name`, its Reprint Group (`null` in none; otherwise `{ref, printings}`: the group's public reference, derived from its internal ID, and the sorted public references of the group's printings that the active catalog generation holds and has not withdrawn, exactly the printings the private check reads) and the effective card attributes of `catalog_card_attribute` (null is unknown). Each listed printing's facts are in its own format record. It is part of the Printing target: it has the Printing record's `revision`, goes in the same compare-and-swap and is rebuilt with it. Any change to a fact it carries must therefore re-stamp the Printing in the same transaction. Migration 036's triggers do that for derived attributes (a value change, not a rules-version-only rewrite), reviewed attribute corrections, a Printing's `identity_id`, a Card Identity's key or name, and Reprint Group membership, through `catalog_stamp_format_facts(printing_ids)`. A membership change re-stamps the Printings that moved and every Printing of the groups they left and joined, since each member's record lists the group's printings. Since migration 037 those group triggers sit on the stored effective membership (`catalog_reprint_group_membership`), which triggers on the derived, linked and assigned group tables keep current, so automatic regrouping, maintainer-reviewed merges, splits, joins and restores, and Card Identity merges all stamp the same way. A writer of those tables takes the public clock (`catalog_begin_correction()`) first, as imports, attribute decisions, Reprint Group and Card Identity decisions and `scripts/derive_card_attributes.py` do. Re-stamping moves only the Printing's `public_revision`: its Live state, its Editions and their mapping revisions stay as they are.

Contradictions are judged on the inputs a rule reads, not on the whole source value. Live reads the export candidate's category, name, `localId` and `set.id`; marketplace matching reads the correspondence, the TCGplayer block's product IDs by variant key and `thirdParty.tcgplayer`. A change to anything else (a regulation mark, a Cardmarket ID, a variant ID) is enrichment: Live and marketplace state stay as they are, and the mapping revision (which quotes are keyed on) does not move. A change that moves a derived card attribute, such as a regulation mark, still republishes the Printing's records at a new revision, because the attribute is a public format fact. Rejections stay keyed on the full source fingerprint.

Rules are code, and a changed rule digest deactivates the approved rule. A new Live set code therefore ships as a new `LiveRulesV2` next to V1, never as an edit of V1; `test_registered_rule_digests_are_pinned` guards every registered version. A deprecated or replaced Edition gives up its verified product and price slot (it becomes unmapped, `reviewed_unmapped`) so its replacement can be verified.

`quote_lookup` names the source card and the variant key but not the product, so two rules keep it honest. First, an Edition is priced only when the product it publishes belongs to that variant block: a maintainer `correct` keeps its `quote_variant` only while the Edition's source block for that variant key (its own, or the card's block it borrowed; see [prices](prices.md)) holds the reviewed `productId`; otherwise the Edition is published verified but unpriced (`quote_variant` NULL). Second, one `(Printing, quote_variant)` price slot belongs to a single verified Edition, whatever product its sibling holds (code check plus the unique index `catalog_edition_verified_printing_slot`). **Obligation for the quote writers (tickets 07 and 08):** before storing a quote under `quote:<ref>:<mapping_revision>`, check that the fetched variant block's `productId` equals the published `product_id`; a mismatch is `absent`, never a quote.

### Delivery

Every correction takes its `public_revision` from one PostgreSQL clock row that stays locked until commit, and a trigger enqueues the changed target in `catalog_public_outbox` in the same transaction. A drain (`drain`) selects pending targets ordered by `(priority, sequence)`, so quarantines and suspensions go first. For each target it re-reads current committed PostgreSQL state and compares the revision with what is stored:

- Stored revision lower (a missing record counts as -1, a ticket-04 record without a revision as 0): write.
- Equal revision and equal value: mark delivered; nothing is written (replay is free).
- Equal revision, different value: write nothing; the row stays pending with `last_error=RevisionValueMismatch`. The one exception is a Printing whose only differing record is its format record: format facts have no fail-closed state and PostgreSQL is their only source, so the record is written (such a difference means a fact changed without a stamp, for example on a runtime older than migration 036's triggers).
- Stored revision higher than PostgreSQL's: write nothing; the row stays pending with `last_error=StoreAhead`. Run the rebuild.

An Edition's catalog and quarantine records always go in the same compare-and-swap, as do a Printing's catalog and format records; one compare-and-swap holds at most 64 Editions or 64 Printings (128 keys). A lost compare-and-swap rebuilds from PostgreSQL instead of trusting the stale read. A stalled or late drainer can therefore never write an older revision over a newer one, and an invalidation cannot be overtaken by a stale clear. Rows are marked delivered only up to the revision actually stored.

No PostgreSQL transaction or row lock is held during store I/O. A session advisory lock (914706) keeps one drainer running; correctness does not depend on it. A busy drain reports `pending`, and the holder re-checks once after unlocking. There is no scheduler: the drain runs after the commit of a catalog import, a missing-card approval, a metadata decision, an attribute decision, `scripts/derive_card_attributes.py` and a rule activation (`publish_catalog_best_effort`, a shim over `drain`), and from the rebuild script; it never runs at the start of a decision path. `drain` COMMITS on its connection, so it raises `DrainMisuse` for a connection with an open transaction (the shim lets that error through) and is called only after the caller's own commit. Request paths use a short budget and report `public_delivery: delivered|pending`. A request passes its `printing_ids`, and that Printing and its Editions are delivered before any unrelated backlog. A rule (de)activation can change thousands of targets, so when anything is still pending after its short drain it starts `python -m app.catalog_import --drain` in a detached session, an unbounded drain that waits out a busy lock; until it finishes the owner sees `pending` (rerun `scripts/backfill_public_catalog.py` if it stays pending). Every drain also checks that the store still holds the most recently delivered targets at their delivered revisions, and re-enqueues everything when it does not (an older store copy or a replaced store). The outbox is per database, so tests empty it around each test. Rows whose target no longer exists are marked delivered without a write (`last_error=TargetMissing`).

A records-store outage (`ProjectionUnavailable`) never rolls back PostgreSQL. The row stays pending with `attempts` and `last_error=ProjectionUnavailable`; the next drain delivers it. The owner operations status reports `catalog_outbox_pending` and `catalog_outbox_oldest_seconds`. Anonymous readers see the previous eligibility until delivery, so a nonzero pending count is the lag to watch. There is no owner "retry delivery" endpoint.

### Readers fail closed

`marketplace_states(store, edition_refs, deadline)` reads `catalog:edition` and `quarantine:edition` for all references at one pinned generation, then reads quote state with `quote_states(..., generation=g)` at that same generation. An Edition is `unknown` (ineligible) if either record is missing or malformed, if their `revision` or `mapping_revision` differ, or if it is quarantined or not verified. A verified Edition is product-eligible when `product_id` is set, and price-eligible when `quote_lookup` is set. `live_states(store, printing_refs, deadline)` does the same for `catalog:printing`, and `format_facts(store, printing_refs, deadline)` for `catalog:format`: a missing or malformed record is `None`. The format route reads the records of every listed Reprint Group printing in a second read pinned to the first read's generation, and treats a row as unproven when any of them is missing, malformed or names another group. Quote writers (tickets 07 and 08) must include the `quarantine:edition:<ref>` version in `expected` on every fenced write and write only the current `mapping_revision`.

### Recovery

`scripts/backfill_public_catalog.py` (the name is kept) rebuilds the records from PostgreSQL. It first scans the store for the highest stored revision (`store_max`) and for records PostgreSQL does not explain, advances the clock with `greatest(revision, store_max)`, marks each unexplained target `quarantined` or `suspended` with reason `recovery_conflict` at a revision above `store_max`, then re-enqueues and delivers every target. It never initializes the store (run `init_public_records.py` first), exits 1 when the store is unreachable or delivery cannot finish, and a second run writes nothing. See `docs/operations/local-recovery.md` for the R1 to R3 procedures.
