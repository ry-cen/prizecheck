# AWS cost-envelope validation

**Researched:** 2026-08-05  
**Decision question:** Can the proposed AWS serverless topology stay below $10/month at idle and support 1,000 registered users, 200 monthly active users (MAU), one heavy collector with up to 25,000 distinct Holdings, and 10,000 public deck views per month?

## Conclusion

**Yes, conditionally.** The topology has **no unavoidable always-on infrastructure charge** when it uses on-demand/serverless service modes and the CloudFront Free flat-rate plan. A conservative no-credit estimate for a modest implementation of the agreed envelope is approximately **$1.50-$3.00/month**, excluding domain registration, taxes, AWS Support, and unrelated account usage. True traffic-idle cost is effectively only stored bytes and DynamoDB point-in-time recovery (PITR), normally **well below $1/month** at MVP data sizes.

The stated envelope does not, by itself, guarantee a sub-$10 bill: it caps a heavy collector at 25,000 Holdings but does not cap how many of the 1,000 registered users are heavy, total table/index bytes, authenticated request volume, or log volume. For example, if all 1,000 users stored 25,000 Holdings, that is 25 million Holding records. At an illustrative 1 KB of total table/index storage per Holding, private-data storage plus PITR alone is about `25 GB × ($0.25 + $0.20) = $11.25/month`, before catalog data or requests. The destination spec therefore needs an aggregate storage budget as well as the per-user limit.

The sub-$10 target is therefore feasible with substantial margin, but it is a **configuration invariant**, not an automatic property of AWS. A NAT Gateway, paid CloudFront tier, standalone pay-as-you-go WAF, customer-managed KMS keys, SES dedicated IP, verbose/unbounded logs, or provisioned Lambda concurrency would each weaken or immediately break the budget.

Use a single AWS Region for application resources (prefer `us-west-2` for the expected operator location) and validate the exact region-specific estimate in AWS Pricing Calculator before deployment. Dollar examples below use the public US rates shown by AWS; prices can vary by Region and can change.

## Cost model

The agreed envelope does not specify sessions or API calls per active user, so this estimate makes those variables explicit:

- 200 MAU, each with 20 sessions/month and 20 API calls/session: 80,000 authenticated API calls.
- 10,000 anonymous public deck views, one uncached API lookup each: 10,000 API calls.
- 100,000 total API Gateway/Lambda requests after allowing 10,000 health, deployment, and operational calls.
- 1,000 OTP/verification emails/month (five per MAU), deliberately above one login per user.
- Up to 1 million DynamoDB write request units and 1 million read request units/month, including inventory transactions, projections, public reads, and a batched catalog-generation import.
- Up to 6 GB total DynamoDB table-and-index data: at most 1 GB of private application data (including denormalized records for one 25,000-Holding collector) and 5 GB of rebuildable catalog/search data. This is a cost-model assumption, not a limit established by the original load envelope.
- PITR enabled only on the private application table. The catalog table is restored by a new catalog generation rather than paid continuous backup.
- One CloudFront distribution serving the SPA and proxying `/api/*`, below 1 million viewer requests and 100 GB transferred per month.
- Lambda execution below 1 million invocations and 400,000 GB-seconds, CloudWatch logs below 5 GB/month, and no more than 10 standard-resolution alarm metrics.
- CI below the GitHub Free allowance of 2,000 hosted-runner minutes and 500 MB of artifact storage per month.

These assumptions are intentionally more expensive than the named public-view envelope while remaining plausible for 200 MAU. They should become deployment budgets/alarms, not remain informal estimates. In particular, target **at most 5 GB total DynamoDB table/index storage for the MVP and alert before 15 GB**; the latter leaves limited room under $10 and is not a desired operating point.

At the stated high-side assumptions, a defensible monthly subtotal is:

- CloudFront/S3/Cognito/Lambda/EventBridge/SQS/CloudWatch/CI: **$0** while inside their allowances.
- API Gateway: **$0.10**.
- SES: **$0.10-$0.16**.
- DynamoDB: approximately **$0.75-$2.45**, depending mainly on actual catalog bytes and whether free storage benefits apply.
- Total: approximately **$0.95-$2.71**, rounded to a planning range of **$1.50-$3.00** for small unmodeled request, storage, and log charges.

Do not use promotional AWS credits to justify the conclusion. Credits can make the initial bill $0, but the architecture remains below the target at public pay-as-you-go rates without them.

## Required cost guardrails

1. **Use one CloudFront Free-plan distribution.** Route static paths to private S3 and `/api/*` to API Gateway. Attach the Route 53 hosted zone to that plan if a custom domain is used. This avoids separate WAF and hosted-zone floors while keeping the application inside five cache behaviors.
2. **Keep Lambda out of a VPC.** DynamoDB, SQS, EventBridge, SES, and the public TCGdex endpoint do not require a NAT Gateway for this design. Do not add a NAT Gateway, interface VPC endpoints, provisioned concurrency, or Lambda Managed Instances.
3. **Use AWS-owned encryption keys.** Default server-side encryption avoids the monthly fee and API-call costs of customer-managed KMS keys. Introduce a customer key only after an explicit security requirement and budget decision.
4. **Use DynamoDB on-demand with throughput and storage caps.** Measure consumed capacity in catalog imports, batch queue messages, avoid scans, and put PITR only on the user-data table. Target at most 5 GB across tables and indexes, alert before 15 GB, and verify actual per-Holding/index bytes with a representative 25,000-Holding fixture. Do not pre-warm tables.
5. **Bound observability.** Use structured compact logs, redact sensitive fields, set 14-30 day retention, keep standard alarm metrics at 10 or fewer, and do not enable X-Ray, Container Insights, detailed API access logs, or high-cardinality custom metrics by default.
6. **Use SES shared sending.** Switch to à-la-carte pricing if available and cheaper for the account; otherwise Essentials is still negligible at OTP volume. Do not use dedicated IPs, Mail Manager, Virtual Deliverability Manager, or large message attachments.
7. **Put budget controls around both providers.** Create free AWS alert-only budgets at $5, $8, and $10 actual/forecast thresholds, recognizing that AWS Budgets reports with delay and is not a hard spending cap. Configure GitHub Actions to stop paid overage. Also alarm on API requests, Lambda errors/throttles, DynamoDB consumed capacity/throttles, SQS DLQ depth, and log ingestion.
8. **Treat catalog synchronization as batch work.** Prefer weekly full generations or upstream-delta-aware daily sync, put multiple small records in each SQS message, limit worker concurrency, and promote a generation only after completion. A naive daily full re-import with one message and several writes per card remains likely affordable at this scale, but wastes SQS, Lambda, DynamoDB, and log allowances.

## Budget breakers and scaling thresholds

- **NAT Gateway:** an hourly resource plus data processing; it is incompatible with the target before meaningful traffic and is unnecessary here.
- **Paid CloudFront/WAF:** CloudFront Pro starts at $15/month. A separately configured pay-as-you-go WAF also introduces fixed web-ACL/rule charges. Stay on the Free plan until its sustained baseline is genuinely exceeded.
- **CloudWatch:** every 10 GB of billable log ingestion at a representative $0.50/GB consumes about $5. Keep payloads out of logs and enforce retention.
- **API traffic:** at $1/million HTTP API calls, API Gateway alone reaches $10 around 10M calls/month. Throttling and CloudFront caching for anonymous deck snapshots preserve headroom.
- **DynamoDB storage/backups:** at representative rates, each 10 GB costs about $2.50/month for Standard storage plus $2/month if PITR is enabled. This is why catalog PITR must remain off.
- **Authentication:** 200 MAU is free; Cognito Essentials begins charging above 10,000 MAU. SES stays small at OTP-only volumes, but bot-driven OTP abuse must be rate-limited by email/IP and monitored.
- **CI:** a private GitHub Free repository starts billing/blocking beyond 2,000 runner minutes or included artifact storage. Keep artifacts short-lived and avoid deploys on every branch push.

## Decision for downstream tickets

Adopt the proposed serverless topology with these locked cost choices: one Region, one CloudFront **Free flat-rate** distribution, private S3 origin, HTTP API, non-VPC on-demand Lambda, two DynamoDB on-demand tables with a 5 GB aggregate target and 15 GB alert threshold, PITR only for private application data, Cognito Essentials email OTP through SES shared sending, EventBridge Scheduler, batched standard SQS with DLQ, AWS-owned encryption keys, finite CloudWatch retention with no more than 10 alarm metrics, alert-only AWS Budgets, and GitHub Actions OIDC within included minutes.

Under those constraints, **sub-$10 idle is technically validated for a bounded MVP realization of the agreed envelope**, not for every workload the current wording could permit. Add the 5 GB target/15 GB alert threshold and explicit API/log caps to the destination spec. Revisit the architecture before enabling any paid CloudFront tier, NAT/VPC networking, customer-managed KMS keys, expanded observability, catalog PITR, or sustained traffic above 1M CloudFront requests / roughly 10M direct HTTP API calls per month.
