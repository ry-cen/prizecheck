# Resolution — Destination contracts and remaining compatibility evidence

The [export investigation](https://github.com/ry-cen/prizecheck/issues/36) found Pokémon's first-party confirmation of text import, Limitless's export/ALT guidance, TCGplayer's documented typed Mass Entry grammar, and the main Limitless site's observed TCGplayer link. [Cited findings](../research/deck-export-formats.md) distinguish documented, observed, inferred, and unverified details.

The main Limitless site's observed affiliate destination uses `productline=Pokemon` and `c` segments shaped `quantity-TCGplayerProductId`, separated by `||`. Typed Mass Entry text is a separate contract using quantity, card name, optional set and collector number. Do not confuse either representation with TCGdex identifiers or assume a product ID identifies every physical finish/condition.

Initial web extraction and a locked computer-use surface did not yield raw clipboard bytes. Approved read-only HTTPS source inspection subsequently verified the main site's first-party clipboard formatter: category headings use `Category: count`, ordinary rows use `quantity name SET number`, groups are separated by blank lines, and no Total Cards footer is added. The helper includes promo/subset/Energy mappings detailed in the research. This source observation is distinct from successfully running the button or importing the output into Live. Pokémon's support page does not publish a formal grammar; destination acceptance, special mappings, and empty-category behavior remain [open verification work](https://github.com/ry-cen/prizecheck/issues/40).

This completes the evidence investigation without approving a serializer. The [export contract decision](https://github.com/ry-cen/prizecheck/issues/38) must settle default action, unresolved-card behavior, mapping specificity and fallback. Actual destination compatibility needs its own evidence; neither a research note nor a plausible sample establishes it.
